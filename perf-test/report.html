⚠ 발견 — 409가 아니라 500이 난다
설계상 두 번째 관리자부터는 다른 관리자가 이미 수정했습니다 라는 409 응답을 받아야 한다. 하지만 완전 동시 요청 12건 전부 500 Internal Server Error로 응답했다. 백엔드 로그를 보면 원인은 CannotAcquireLockException: Deadlock found when trying to get lock — 5개의 UPDATE가 동시에 같은 행을 잠그려다 InnoDB 데드락이 발생한 것이다. GlobalExceptionHandler는 ObjectOptimisticLockingFailureException과 IllegalStateException만 409로 매핑해 두어서, 데드락 예외는 최하단 500 핸들러로 떨어진다.

있는 그대로: 지금은 차이가 거의 없다
incidents.severity에 인덱스가 걸려 있어 COUNT 쿼리 자체가 이미 1~5ms대다. 장애 약 150건, 일일 통계 30행 규모의 로컬 데이터로는 두 방식이 통계적으로 구분되지 않는다. 스냅샷 테이블의 실익은 보통 (a) 여러 테이블을 JOIN하는 복잡한 집계, (b) 인덱스 없는 대용량 테이블 풀스캔, (c) 동시 요청 폭주로 DB 커넥션·락이 경합하는 상황에서 드러난다 — 지금 이 API 쌍은 그 조건에 해당하지 않는다는 점을 그대로 보고한다.
